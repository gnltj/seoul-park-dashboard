# MapDashboard 검증 결과

검증일: 2026-10-28 (Asia/Seoul). 실제 브라우저에서 실행한 결과와 CPython 단위 테스트 결과를 구분해 기록합니다.

## 팀 공유 전 재검증

`feature/map-dashboard` 브랜치의 별도 Clone 폴더에서 단위 테스트 23개와 브라우저 통합 테스트 22개를 다시 실행해 전부 통과했습니다. 브라우저 재검증 주소는 `http://127.0.0.1:8767/demo/index.html?test=1`이며, 아래 출력 기록은 이번 재검증 결과로 갱신했습니다.

- 검수 원본 폴더의 전체 파일 해시 및 파일 목록이 유지됨을 확인했습니다.
- `map_dashboard.py`, `run_demo.py`, `demo/`, `tests/`의 코드 11개 파일이 검수 원본과 바이트 단위로 일치합니다.
- 기존 팀장님의 루트 README, .gitignore, .nojekyll의 내용과 해시를 보존했습니다.
- 설명 문서를 `docs/mapdashboard/`로 정리하고 상대 링크와 데모 HTTP 경로를 확인했습니다. 실행 명령은 저장소 루트 기준입니다.
- Windows 도우미에서 개인 PC 캐시 경로를 제거했습니다. Python Launcher 또는 PATH의 Python을 사용하는 동작을 `--help`로 확인했습니다.
- 기존 GitHub Pages 설정과 배포 파일은 변경하지 않았으며, 이 기록은 최종 배포 검증을 의미하지 않습니다.

## 실행 환경

- Windows 로컬 작업 폴더: `저장소 루트`
- 단위 테스트: 기존 Codex Python 3.12.14, 표준 `unittest`
- 브라우저: Codex 내장 Chromium 기반 브라우저
- 브라우저 런타임: PyScript 2026.7.3 / Pyodide 0.29.0
- 지도: Leaflet 1.9.4 / OpenStreetMap 타일
- 테스트 데이터: MockPark 6개 (모두 가상), 좌표 유효 5개
- 테스트 URL: `http://127.0.0.1:8765/demo/index.html?test=1`

## 실행 도우미 확인

- 독립 개발 당시 `실행.cmd --help`로 Python 연결을 확인했습니다. 팀 공유본은 개인 PC 런타임 경로를 제거하고 `py -3` 또는 PATH의 `python`을 사용하도록 정리했습니다.
- `run_demo.py --port 8766 --no-browser`를 실제 실행해 `/demo/index.html`과 `/map_dashboard.py`의 HTTP 200을 확인하고 해당 점검용 프로세스를 종료했습니다.
- 브라우저 검증에 사용한 8765 로컬 서버는 데모 미리보기용으로 실행했습니다. 같은 포트를 사용 중이면 기존 서버를 종료하거나 `--port 8766`을 사용하세요.

## 검증 중 수정한 사항

- PyScript의 단순 인터프리터 버전 문자열이 상대 URL로 해석되어 로딩에 실패했습니다. Pyodide 전체 CDN URL로 지정해 실제 실행을 확인했습니다.
- 행 클릭 이동에 애니메이션을 비활성화하여 연속 클릭 시 이전 확대 애니메이션과의 간섭을 방지했습니다.
- 팝업 자동 패닝 때문에 지도 중심이 정확히 마커와 같을 필요는 없습니다. 대상 마커가 화면 안에 있고 확대 수준이 맞는지 검사합니다.
- 닫히는 팝업의 DOM이 잠시 남을 수 있어 통합 테스트에서 현재 마커의 열린 팝업 DOM을 검사하도록 수정했습니다.
- 실행 도우미는 UTF-8 모드로 Python을 호출해 한글 콘솔 출력의 인코딩 문제를 줄였습니다.

## 미검증 범위

- 첨부되지 않은 프로젝트 PDF 및 실제 엑셀 구조와의 대조
- 실제 133개 공원 데이터, 실제 Park/ParkManager/DataLoader와의 통합
- 승진 팀원의 실제 HTML/CSS에 연결했을 때의 배치와 요소 타입
- 별도 설치 Chrome/Edge/Firefox/Safari 전체 버전에서의 교차 브라우저 테스트
- 네트워크 차단 상태에서 CDN/지도 타일을 사용할 수 있는지 여부 (현재 인터넷 필요)
- GitHub Pages 배포 환경 (이번 작업에서는 배포하지 않음)

원본 데이터의 정제 정확성이나 실제 Manager의 필터/정렬 정책까지 검증했다고 해석하면 안 됩니다. Mock의 알고리즘은 화면 연결을 검증하기 위한 테스트 대역에 한정됩니다.
