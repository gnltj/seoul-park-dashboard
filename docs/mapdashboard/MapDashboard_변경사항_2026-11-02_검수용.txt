클래스 구조 변경 요약

기존에는 MapDashboard 클래스 하나가 입력칸, 지도, 공원 목록,
전체 화면 갱신을 모두 담당했습니다.

수정 후에는 이 역할을 다음 4개 클래스로 나눴습니다.

1. FilterPanel — 입력 담당
   구 선택과 최소·최대 면적 입력을 읽고,
   입력이 바뀌면 Dashboard에 알려 줍니다.

2. MapView — 지도 담당
   지도와 공원 마커를 표시하고 팝업 내용을 만듭니다.
   공원을 선택하면 해당 위치로 지도를 이동합니다.

3. ParkListView — 목록 담당
   공원 목록과 표시 개수를 보여 줍니다.
   정렬 기준과 방향을 관리하고, 선택한 공원을 Dashboard에 알려 줍니다.

4. Dashboard — 전체 흐름 담당
   위 3개 화면 클래스와 ParkManager를 연결합니다.
   ParkManager에 필터·정렬을 요청한 뒤 지도와 목록을 갱신하도록 합니다.
   화면을 직접 그리지는 않습니다.

팝업 내용을 만드는 역할도 Park에서 MapView로 옮겼습니다.
Park는 공원 정보와 위치·정렬값을 제공하는 역할을 유지합니다.

즉, 기존 기능을 없앤 것이 아니라 MapDashboard에 모여 있던 일을
입력·지도·목록·전체 흐름으로 나눠 각 클래스의 역할을 명확히 했습니다.

우리 담당: FilterPanel, MapView, ParkListView, Dashboard
팀원 담당: Park, DataLoader, ParkManager
전체 구조: 총 7개 클래스
